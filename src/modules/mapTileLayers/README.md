# Свои тайлы карты (mapTileLayers)

Добавляет в игровой переключатель слоёв два своих пункта подложки поверх четырёх игровых (OSM, CartoDB, спутник Google, пустая). Игрок указывает адрес своего тайлового сервера и выбирает, показывать тайлы как есть или инвертировать их в тёмный вид.

## Возможности для игрока

- Поле для шаблона адреса тайлов (`https://example.com/tiles/{z}/{x}/{y}.png`) прямо в окне слоёв.
- Пункт "Свои тайлы": подложка рисуется так, как её отдаёт сервер.
- Пункт "Свои тайлы (тёмная)": подложка инвертируется, чтобы светлая карта не слепила в тёмном интерфейсе.
- Оба пункта недоступны, пока адрес не введён.
- Выбор и адрес переживают перезагрузку страницы.
- Возврат на игровой слой и выключение модуля возвращают ту подложку, которую рисует игра.

## Архитектура

### Перехват источника тайлов

Игра держит подложку в одном слое OpenLayers (`.ol-layer__base`) и переставляет ей источник функцией `setBaselayer` (`refs/game/script.js`). Вызывается она не только по клику в переключателе слоёв: ещё при первой отрисовке карты и при смене темы игры.

Поэтому модуль не просто ставит свой источник, а подменяет слою метод `setSource` (`lockGameSource`): пока выбраны свои тайлы, игровые вызовы только записываются, но не применяются. Иначе смена темы вернула бы игровую подложку поверх выбранной игроком.

Записанный вызов не выбрасывается: при возврате на игровой слой `unlockGameSource` применяет именно тот источник, который игра запросила последним. При выключении модуля вместо него применяется источник, сохранённый до первой подмены: игра могла обработать наше значение radio, которого не знает, и запросить мусор.

### Фильтр подложки и тема игры

Своя тёмная подложка получается CSS-фильтром `invert(1) hue-rotate(180deg)`, светлая - явным `filter: none`.

Фильтр вешается на сам слой `.ol-layer__base`, а не на его canvas, потому что этот же элемент фильтрует игра:

```css
:root[data-theme='dark'] .ol-layer__base[data-code='osm'] {
  filter: invert(1) hue-rotate(180deg) brightness(0.75) grayscale(1);
}
```

Фильтры предка и потомка не отменяют друг друга, а перемножаются. Пока наш фильтр висел на canvas, `filter: none` не снимал игровую инверсию, а наша инверсия ложилась поверх игровой и давала двойную.

Оба условия игрового правила модулю неподконтрольны:

- `html[data-theme='dark']` игра выставляет сырым значением своей настройки темы, а `prefers-color-scheme` в её CSS нет; значит правило включает только явно выбранная тёмная тема, а не системная при теме "авто".
- `data-code` игра штампует своей настройкой `base`, то есть последним выбранным игровым слоем. Наши radio не подключены к игровому обработчику, модуль игровую настройку `base` не пишет, и там остаётся слой, выбранный до переключения на свои тайлы.

Отсюда прежняя недетерминированность: тёмная подложка выцветала только у игрока с явно выбранной тёмной темой, у которого последним игровым слоем был OSM.

Разрешает конфликт `!important`: важное авторское объявление выигрывает у обычного независимо от специфичности, а игровое правило обычное. Определять тему, следить за `data-code` или переставлять его не нужно.

Стиль живёт ровно столько, сколько активны свои тайлы: возврат на игровой слой и выключение модуля его снимают, иначе он продолжил бы подавлять уже игровую тёмную подложку.

### Встраивание в окно слоёв

Окно `.layers-config` в текущей игре лежит в разметке постоянно, поэтому модуль встраивается в уже найденное окно при включении, а `MutationObserver` на `body` остаётся для версий, где окно создаётся по требованию. Свои пункты вставляются после игрового спутника Google, найденного по `input[name="baselayer"][value="goo"]`; вставка переживает появление новых секций в окне (Objects, Highlighter в SBG 0.6.1).

При выключении модуль снимает свой обработчик, удаляет свои элементы и только потом возвращает отметку на игровой radio: событие `change` должно дойти до игрового обработчика, а не до нашего.

## Настройки

Отдельной панели настроек у модуля нет, всё управление в игровом окне слоёв. Модуль включён по умолчанию.

| Ключ                   | Значение                                              |
| ---------------------- | ----------------------------------------------------- |
| `svp_mapTileLayerUrl`  | Шаблон адреса тайлов                                  |
| `svp_mapTileLayer`     | Выбранный вариант: `svp-custom` или `svp-custom-dark` |
| `svp_mapTileGameLayer` | Игровой слой, выбранный до переключения на свои тайлы |

## Файловая структура

| Файл                    | Назначение                                                                                            |
| ----------------------- | ----------------------------------------------------------------------------------------------------- |
| `mapTileLayers.ts`      | Определение модуля, перехват `setSource`, фильтры подложки, встраивание пунктов в окно слоёв          |
| `mapTileLayers.test.ts` | Тесты перехвата и восстановления источника, встраивания в окно слоёв, элемента-цели фильтра, хранения |
| `styles.css`            | Оформление поля адреса тайлов                                                                         |
