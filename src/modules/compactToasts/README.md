# compactToasts

Собирает одновременные ошибки в один блок со счётчиком повторов.

## Что видит игрок

Без модуля каждый отказ - отдельный тост. Серия действий (рисование линий, повторные попытки вне радиуса) засыпает экран стопкой одинаковых сообщений.

С модулем ошибки, живущие одновременно, показываются одним блоком:

```
Недостаточно ключей (x3)
Точка вне зоны действия
```

Повтор сообщения увеличивает счётчик, а не добавляет строку.

## Что в блок не попадает

**Нейтральные сообщения.** Игрок читает их по одному, склеивать незачем. Кроме того, тост с добычей игра создаёт пустым и дописывает содержимое уже после показа (`refs/game/script.js:830-845`) - подмена такого узла стёрла бы игроку список добычи.

**Ошибки из другого места экрана.** Блок собирается отдельно для каждого контейнера: ошибки действий игра вешает внутрь попапа точки (`refs/game/script.js:807`), а отказы рисования показывает на уровне экрана. Смешивать их нельзя - это разные места. Позиция при этом остаётся та, которую задала игра.

## Срок жизни строк

У каждой строки свой срок, а не общий на блок: иначе строка из начала серии доживала бы до её конца и блок только рос бы. Строка живёт столько же, сколько жил бы её тост (обычно 3 секунды), повтор продлевает срок. Истёкшие строки снимаются с живого узла, сам узел живёт до самой поздней строки.

```
0.0 с  ошибка X   -> [X]
2.0 с  ошибка Y   -> [X / Y]
3.0 с  -          -> [Y]        строка X истекла
5.0 с  -          -> блок ушёл
```

## Отвергнутые подходы

**Свёртка длинных сообщений игры.** Трёхстрочный тост про новые регионы (`popups.new-regions`) можно было опознавать по шаблону из локализации игры и заменять строкой вида `Регионы: +3 (1.4 км2)`. Опознавание держалось бы на точной формулировке перевода и ломалось от любой её правки, а выигрыш - одно сообщение из всех, что показывает игра.

**Обрезка по длине.** Оборванная многоточием фраза хуже длинной: игрок не понимает, что потерял.

**Метка в исходнике игры.** Позволила бы отличить ошибку рисования линии от любой другой (по параметрам они одинаковы: общий `apiSend` без опций тоста даёт `error-toast`, `selector: null`, `top center`). Пометить тост можно было бы патчем скрипта игры (`core/gameScriptPatcher.ts`), но литеральный якорь патча ломается от любой правки рядом.

## Использование Toastify

Модуль патчит `Toastify.prototype.showToast` - единственную точку, через которую проходят все уведомления игры. Инстансы не создаёт, а меняет входящий, поэтому учёт `popup_toasts` внутри игры остаётся согласованным.

## Что будет при обновлении игры

Через патч проходят все уведомления игры, поэтому цена ошибки здесь - не сломанная сборка блоков, а сломанные сообщения игры. Защита:

- любая ошибка внутри сборки снимает патч с прототипа и пишет причину в консоль; дальше игра показывает сообщения сама, как без модуля;
- вызов исходного `showToast` вынесен из-под `try`: ошибка самой библиотеки пришла бы игре и без нас, и глотать её нельзя;
- сообщения неожиданной формы (не строка в тексте, пустой текст, нулевая или бесконечная длительность) проходят мимо блока по одному, а не ломают его: пустой текст игра дописывает уже после показа, а сообщению без автоснятия нечем истечь в блоке.

Правило `font-size` для игровых классов тостов (`core/toast.css`) при переименовании классов просто перестаёт применяться.

Опора на внутренности библиотеки (сверено по `refs/toastify/toastify.js`, версия 1.12.0):

| Что                                                   | Зачем                                                           |
| ----------------------------------------------------- | --------------------------------------------------------------- |
| `options.className` подставляется конкатенацией (:64) | класс ошибки проверяется по токену, а не равенством строки      |
| `toastElement.timeOutValue` (:105)                    | снять таймер прежнего узла                                      |
| `removeElement` откладывает удаление на 400 мс (:112) | прежний узел снимаем напрямую, иначе два блока висели бы вместе |
| `options.duration` задаёт срок узла (:105)            | узел доживает до самой поздней строки блока                     |
