# smoothPlayerMarker

Плавное движение маркера игрока между обновлениями GPS.

## Что видит игрок

Без модуля маркер, круги вокруг него и карта в режиме следования прыгают раз в секунду - ровно тогда, когда приходит новый фикс от геолокации. С модулем иконка игрока и круги едут к новой позиции линейно за время, равное интервалу между фиксами, а в режиме следования вместе с ними плавно едет и центр карты.

Точка, которую игра считает позицией игрока, при этом не меняется: расстояния до точек, активность кнопок действий и координаты в панели игрока остаются такими же, как без модуля.

## Почему не подход CUI

В CUI (`refs/cui/index.js:737-842`) интерполированные координаты подаются в саму игровую `movePlayer` 60 раз в секунду. В SBG геометрия `player_feature` - не только картинка:

| Потребитель                                              | Что делает                                           |
| -------------------------------------------------------- | ---------------------------------------------------- |
| `position:` в discover / deploy / attack / draw / repair | уходит на сервер вместе с действием                  |
| `pos` в сообщениях websocket                             | уходит на сервер                                     |
| `isInRange` / `getDistance`                              | решает, доступно ли действие и что показать в попапе |
| `getBearing`, навигация, выбор ближайших точек           | считает направление и расстояния                     |

Подмена этой геометрии означала бы синтезированные координаты в запросах к серверу, то есть нарушение критических запретов проекта (подмена GPS, модификация запросов). Поэтому сглаживается только рендер.

## Что именно сглаживается

Игра рисует маркер массивом стилей: `player_styles[0]` - иконка без собственной геометрии (берёт геометрию фичи), `player_styles[1..3]` - круги радиуса действия, взрыва и максимального взрыва (`ol.geom.Circle` с центром на позиции игрока).

- Иконке один раз ставится геометрия рендера через `Style.setGeometry(point)` (`refs/ol/ol.js:6884`), дальше каждый кадр меняются координаты самой точки.
- Кругам меняется только центр; радиусы остаются игровыми, поэтому анимация взрыва и пересчёт радиуса действия на `moveend` продолжают работать.
- После каждого применённого кадра вызывается `feature.changed()` - без него renderer не пересоберёт план отрисовки. Игра сама делает то же самое на 45 Гц для компаса, так что частота штатная.
- `disable` возвращает иконке геометрию фичи (`setGeometry(undefined)`), а круги - на реальный фикс.

Источник фиксов - игровое событие `playermove`: игра диспатчит его внутри `movePlayer` уже после записи координат, поэтому цель анимации читается прямо из фичи. Повторные вызовы `movePlayer` с той же координатой (игра так перерисовывает маркер при открытии панелей) распознаются как перерисовка и не сбивают ни цель, ни измеренный интервал между фиксами.

## Следование за игроком

Игра центрует карту вызовом `view.setCenter(pos)` в конце `movePlayer`, синхронно после нашего обработчика. Модуль оборачивает `view.setCenter`: вызов с координатой текущего фикса, пришедший в окне фикса, перенаправляется на текущую интерполированную точку, а дальше центр ведут кадры анимации.

- Окно фикса открывается в обработчике `playermove` и закрывается микротаском, поэтому посторонние вызовы `setCenter` (закрытие слайдера рисования, переход по ссылке на точку) проходят насквозь.
- Включённость следования не вычисляется по `localStorage['follow']` и свойствам карты, а наблюдается по факту: игра отцентровала карту на фиксе - значит следование активно на этом интервале.
- Жест пользователя (`view.getInteracting()`) отпускает центр до следующего фикса - так же ведёт себя и нативное следование.
- Если карта угнана дальше порога телепорта, центрирование отдаётся игре: мгновенный доворот вместо долгого линейного полёта.

`view.animate` не используется намеренно: во время анимации OL подавляет событие `moveend` (`refs/ol/ol.js:8169`), а на нём висит догрузка точек в игре (`refs/game/script.js:570-586`) - при длительности анимации порядка интервала фиксов точки перестали бы подгружаться.

## Константы

| Константа                   | Значение | Смысл                                                                                         |
| --------------------------- | -------- | --------------------------------------------------------------------------------------------- |
| `MIN_ANIMATION_DURATION_MS` | 200      | ниже порога линейный ход неотличим от прыжка                                                  |
| `MAX_ANIMATION_DURATION_MS` | 2000     | потолок отставания рендера при длинных паузах GPS                                             |
| `TELEPORT_DISTANCE_METERS`  | 100      | больше - срыв GPS или выезд из туннеля, анимация читалась бы как глитч                        |
| `SAME_TARGET_EPSILON`       | 0.01     | распознавание перерисовки той же координаты                                                   |
| `CENTER_MATCH_EPSILON`      | 0.001    | распознавание игрового `setCenter` из `movePlayer`                                            |
| `MIN_RENDER_STEP_PIXELS`    | 0.5      | кадры с субпиксельным сдвигом не рисуются: движения не видно, а перерисовка карты стоит денег |

Длительность анимации равна измеренному интервалу между двумя последними фиксами, зажатому в `[MIN, MAX]`.

## Отставание и почему нет экстраполяции

Нарисованная позиция отстаёт от игровой максимум на один интервал фиксов. Это осознанная цена: экстраполяция (dead reckoning) убрала бы отставание, но рисовала бы позицию, где игрок ещё не был, и обещала бы кругом радиуса досягаемость, которой нет. Отставание работает в обратную сторону - показывает доступность консервативно.

## Взаимодействие с другими модулями

| Модуль                                             | Пересечение                                                                                    |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `shiftMapCenterDown`                               | оборачивает `view.calculateExtent`, другой метод; его `setCenter` идёт вне окна фикса насквозь |
| `singleFingerRotation`                             | меняет только поворот вида, центр не двигает                                                   |
| `improvedNextPointSwipe`, `refsOnMap`, `drawTools` | читают позицию игрока из геометрии фичи, а её мы не трогаем                                    |
| `largerPointTapArea`                               | меняет допуск попадания по точкам, слоя игрока не касается                                     |

Модуль несовместим с CUI: тот сам подменяет позицию игрока покадрово, и сглаживание накладывалось бы на сглаживание. SVP и CUI и без того не работают в одной вкладке.

## Отказ и деградация

Ошибка в нашей логике логируется один раз за включение с префиксом `[SVP smoothPlayerMarker]`, рендер откатывается к нативному, перехваты остаются в цепочке и пробуют снова на следующем фиксе. Если структура стилей игры не распознана или `ol.geom.Point` недоступен - модуль не трогает рендер вовсе. Если слоя игрока нет (десктоп с отказавшей геолокацией), модуль не включается и пишет предупреждение.

## Файловая структура

| Файл                     | Ответственность                                                            |
| ------------------------ | -------------------------------------------------------------------------- |
| `markerInterpolation.ts` | арифметика и политика: интерполяция, длительность, телепорт, перерисовка   |
| `playerMarkerStyles.ts`  | разбор и мутация игровых стилей маркера, откат к нативному рендеру         |
| `smoothPlayerMarker.ts`  | жизненный цикл, слушатель `playermove`, кадры, обёртка `setCenter`, ошибки |

`markerInterpolation.ts` не знает ни про OL, ни про DOM, ни про часы - время приходит аргументом, поэтому вся политика тестируется вызовами с числами.
