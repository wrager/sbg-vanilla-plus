# removeAttackCloseButton

В режиме атаки кнопка «Атака» превращается в «Закрыть», а кнопка «Закрыть» рядом с «Огонь!» убрана.

## Зачем

Нативная «Закрыть» стоит вплотную к «Огонь!» ([refs/game/index.html:120-127](../../../refs/game/index.html#L120-L127)), поэтому промах по «Огонь!» выкидывает из режима атаки посреди боя. Кнопка выхода уезжает вниз экрана, на место «Атаки», где ничего критичного рядом нет.

## Что делает

- Скрывает `#attack-slider-close` стилем (`display: none !important` - игра управляет видимостью слайдера через jQuery, inline-стиль перебивается только `!important`).
- Пока режим атаки открыт, подписывает `#attack-menu` текстом, снятым с самой скрытой `#attack-slider-close`; при закрытии возвращает снятую подпись «Атаки» и её `data-i18n`.
- Клик по `#attack-menu` в открытом режиме уводится на нативную `#attack-slider-close`.

## Откуда берётся текст

С кнопки, которую модуль скрывает. Игра переводит разметку по `data-i18n` один раз при старте ([refs/game/script.js:135](../../../refs/game/script.js#L135)), поэтому в `#attack-slider-close` уже лежит готовая подпись на языке игрока - ни ключей перевода, ни собственной пары en/ru модулю не нужно. По той же причине возврат подписи «Атака» идёт из снимка: смена языка в настройках игры делает `location.reload` ([refs/game/script.js:1958-1959](../../../refs/game/script.js#L1958-L1959)), значит внутри сессии снятый текст не устаревает.

Кнопки нет или у неё пустой текст - подпись не подменяется вовсе: «Атака» лучше пустой кнопки, а выход остаётся за нативным toggle.

## Почему клик перенаправляется, а не отдаётся игре

Игровой обработчик `#attack-menu` ([refs/game/script.js:1550](../../../refs/game/script.js#L1550)) сам по себе закрывает режим повторным кликом, но перед этим читает `inventory-cache` и уходит в тост «нет оружия», если израсходован последний катализатор. Режим при этом остаётся открытым, а нативная кнопка выхода скрыта нашим стилем - выйти становится нечем.

Обработчик `#attack-slider-close` ([refs/game/script.js:1803](../../../refs/game/script.js#L1803)) делает полный выход: прячет слайдер, возвращает офсет вида, снимает подсветку радиуса атаки, пересчитывает позицию игрока. Перенаправление на него переиспользует игровую логику вместо её дублирования.

Перехват стоит на `document` в capture-фазе: игровой обработчик висит на самой кнопке, и `stopPropagation` до target-фазы не даёт ему сработать. `stopImmediatePropagation` не используется - остальные capture-слушатели документа клик получают.

## Состояние подписи ведётся от слайдера

Режим атаки закрывается не только через кнопку: игра прячет слайдер при входе в режим рисования ([refs/game/script.js:1029](../../../refs/game/script.js#L1029)). Поэтому подпись синхронизируется по классу `hidden` на `.attack-slider-wrp` через MutationObserver, а не по собственным кликам. Тот же вызов синхронизации выполняется на `enable`: модуль могли включить в настройках при открытом режиме.

## Чего НЕ покрывает

- Игра обновилась и `#attack-slider-close` в разметке нет - подпись остаётся «Атака», клик отдаётся игре, выход работает нативным toggle, но ловушка с последним катализатором возвращается.
- Подпись не меняется, если в разметке нет `#attack-menu` или `.attack-slider-wrp`: модуль остаётся только стилем.
