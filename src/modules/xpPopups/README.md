# xpPopups

Показывает полученный опыт всплывающим значением по центру верхней части экрана.

## Что видит игрок

После любого действия, за которое начисляется опыт, под верхней панелью появляется значение вида `+130 очк.`: всплывает, поднимается и растворяется за 1.2 секунды. Серия действий подряд выстраивается в стопку - каждое следующее значение встаёт под предыдущим, а не поверх него. Одновременно на экране их не больше пяти: при более длинной серии самое старое снимается, и новое занимает освободившееся место.

Нативная подпись прироста в строке «Опыт» верхней панели, пока модуль включён, скрыта: две подписи об одном событии - шум. У большинства игроков она и так не видна - модуль `enhancedMainScreen` (включён по умолчанию) прячет всю строку целиком, так что модуль не столько переносит подпись, сколько возвращает потерянную обратную связь.

Настроек у модуля нет.

## Источник данных

Опыт приходит только в ответах на действия и сходится в `handleExpChange` игры (refs/game/script.js:2776). Формат везде одинаковый: `{ xp: { cur, diff } }`.

| Действие                               | Запрос               | `handleExpChange`    |
| -------------------------------------- | -------------------- | -------------------- |
| Изучение точки                         | `POST /api/discover` | script.js:827        |
| Простановка и апгрейд ядра             | `POST /api/deploy`   | script.js:947        |
| Атака                                  | `POST /api/attack2`  | script.js:1728       |
| Рисование линии                        | `POST /api/draw`     | script.js:1801       |
| Зарядка из попапа точки и из инвентаря | `POST /api/repair`   | script.js:959, :3021 |

Других источников опыта у клиента нет: `/api/use` опыта не даёт (script.js:1273-1300), а `/api/profile` отдаёт суммарный `xp` числом (script.js:3305), а не прирост.

`GET /api/draw` - это список возможных целей рисования (script.js:1005), опыта в нём нет. Отделяется по методу, а не по форме тела: метод - контракт, форма тела - нет. Игра шлёт метод строчными (`'post'` в `apiSend`, `'get'` в `apiQuery`), поэтому значение нормализуется перед сравнением.

## Почему обёртка fetch

Правило проекта (docs/agent/rules.md:38) ставит text-patch через `installGameScriptPatcher` выше runtime-обёртки. Здесь выбрана обёртка - решение принято при постановке задачи, расхождение с правилом озвучено до начала работы. Довод в пользу выбора: контракт `POST /api/*` с полем `xp` стабилен между версиями игры, тогда как поисковый литерал text-патча ломается на любой правке `script.js` и требует обновления с каждым релизом игры.

Патч ставится один раз за жизнь страницы, а `disable` только сбрасывает флаг - как в `refsLayerSync` и `refsOnMap`. Полностью снять обёртку, вернув сохранённую ссылку, нельзя: модуль включается в блоке `ui`, то есть раньше `refsLayerSync`, `refsOnMap` и `drawingRestrictions`, и восстановление выкинуло бы из цепочки их обёртки.

Тело ответа читается клоном (`response.clone()`): игра читает то же тело в `apiSend` (script.js:4003), а тело одноразовое. Наружу уходит исходный промис - ответ не подменяется.

## Устройство рендера

Слой `.svp-xp-popup-layer` - `position: fixed` нулевой высоты с абсолютно спозиционированными детьми: появление и удаление значения не трогают раскладку игрового интерфейса. Верх слоя выставляется замером нижней кромки `.topleft-container`, потому что высота панели зависит от режима `enhancedMainScreen`, языка и размера шрифта. Замер делается один раз в начале серии - за время жизни значений панель не переезжает.

Движение задано только крайними кадрами анимации, промежуточные трогают лишь прозрачность. Кадр с собственным `transform` в середине превращает участок вокруг себя в почти неподвижное плато: значение выглядит подвисшим, хотя кадры идут исправно.

Место в стопке приходит в CSS отдельной custom property и складывается с движением внутри одного `transform`. Через `top` было бы проще, но это layout-свойство: каждая вставка заставляла бы браузер считать позицию заново. Место закрепляется за значением на всю его жизнь и освобождается при снятии - пересчёт стопки на каждом уходе дёргал бы вверх все оставшиеся значения посреди их анимации.

Длительность анимации объявлена один раз, в `XP_POPUP_ANIMATION_MS`, и попадает в CSS через custom property на слое. Узел снимается по `animationend`; страховочный таймер на ту же длительность плюс запас закрывает случай, когда события не будет (вкладка ушла в фон). Оба пути ведут в одну идемпотентную функцию, так что второй пришедший ничего не ломает.

В скрытой вкладке новые значения не создаются вовсе: кадры там не идут, и вернувшийся игрок увидел бы доигрывающее значение из прошлого.

Единица измерения читается из уже переведённой игрой разметки (`[data-i18n="units.pts-xp"]`), как подпись кнопки в `removeAttackCloseButton`. Через `i18next.t` не идём: на неизвестном ключе i18next возвращает сам ключ, и в значении оказалось бы `+130 units.pts-xp`.

## Отличия от реализации CUI

За образец взята реализация CUI (`refs/cui/index.js:2019-2030`), но её узкие места не повторяются.

| В CUI                                                     | Здесь                                                |
| --------------------------------------------------------- | ---------------------------------------------------- |
| Число выпарсивается регуляркой из локализованной подписи  | Число берётся из JSON ответа                         |
| Источник - MutationObserver на `.xp-diff`                 | Источник - ответ сервера, observer'а нет             |
| Два `setTimeout` на каждое значение                       | `animationend` плюс один страховочный таймер         |
| `setTimeout(100)` вместо принудительного reflow           | Анимация в классе на узле, стартует сама             |
| Таймер удаления на 3000мс не связан с длительностью в CSS | Одна константа на анимацию и на таймер               |
| Таймеры не отменяются                                     | Таймер гасится при снятии узла                       |
| `removeChild` бросает на уже отцепленном узле             | `element.remove()` плюс проверка, что узел ещё живой |
| Количество значений ничем не ограничено                   | Не больше пяти, самое старое вытесняется             |
| Контейнер в потоке `body`, каждая вставка даёт reflow     | Слой вне потока, вставка не трогает раскладку        |
| При выключении ничего не убирается                        | Слой, узлы и таймеры снимаются на `disable`          |

## Известные ограничения

При выключенной игровой настройке `dsvhid` игра сама показывает тост «Изучение: +130 очк.» (script.js:830-838) - на изучении точки игрок увидит и тост, и всплывающее значение.
