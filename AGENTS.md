# Инструкции для агентов

Общая точка входа для Codex и Claude Code. Отвечай пользователю по-русски.

В начале работы прочитай по порядку:

1. [docs/agent/context.md](docs/agent/context.md) — контекст и карта проекта.
2. [docs/agent/rules.md](docs/agent/rules.md) — канонические правила работы.

Перед изменением кода также прочитай `docs/architecture.md`, `docs/dev-principles.md`,
`docs/codestyle.md` и `docs/glossary.md`. Перед работой с игровым DOM/API исследуй `refs/`;
если референсов нет, используй `npm run refs:fetch` согласно правилам проекта.

Проект меняет UI/UX игры. Запрещены подмена GPS, автоматизация игровых действий,
мультиаккаунт и модификация серверных запросов. CUI/EUI — альтернативные реализации для
исследования в `refs/`, а не одновременно работающие со SVP скрипты.

Запрет автоматизации относится и к агенту: не взаимодействуй с интерфейсом игры
через браузер, JavaScript или API. В живой игре допустимо только наблюдение;
интерактивные проверки выполняет пользователь. Автотесты запускай на локальных моках.

## Команды разработки

Установка зависимостей: `npm ci` (Node.js 24 LTS, версия для CI в `.node-version`). Проверки из корня репозитория:

```text
npm run skills:check
npm run typecheck
npm run lint
npm run format:check
npm run test
npm run build
npm run test:build
```

Запускай команды последовательно и останавливайся при ошибке. В Windows PowerShell 5.1
`&&` недоступен: запускай команды отдельно и проверяй код завершения каждой.

Если Jest в Windows-песочнице падает на `EPERM` при записи кэша в `%TEMP%`, используй
`npm run test -- --runInBand --cacheDirectory node_modules/.cache/jest`.

## Завершение работы и PR

- **Соавторство в PR.** При создании и обновлении PR собирай `Co-authored-by` из всех его коммитов в завершающий абзац описания, сохраняя уже указанных соавторов и служебный текст бота. Удаляй дубли по паре имя/email; разные имена с одним email не объединяй. Перед передачей на merge сверяй с текущими коммитами.
- После внесения изменений в PR обновлять его описание, чтобы оно отражало итоговые изменения и фактические результаты проверок, включая ограничения и непройденные проверки. Перед завершением работы сверять описание с текущим diff; в PR ботов сохранять служебную структуру описания.
- Не оставлять незакоммиченные изменения по завершении работы: любые внесённые правки должны быть закоммичены, запушены и находиться либо в `main`, либо в открытом PR.
- После закрытия или вливания PR удалять его remote-ветку. Перед удалением проверять состояние PR и имя его head-ветки; `main` и другие защищённые ветки не удалять.

## Проектные скиллы

Исходники скиллов: `.agents/skills/sbg-*/SKILL.md`. Codex читает их напрямую;
для Claude Code отсюда создаются копии в `.claude/skills/` командой `npm run skills:sync`.
Редактируй только исходники и общие сценарии в `docs/agent/`, затем синхронизируй копии.
Обе папки скиллов хранятся в Git; `npm run skills:check` проверяет отсутствие расхождений.

| Скилл            | Когда использовать                        |
| ---------------- | ----------------------------------------- |
| `sbg-new-module` | Создание нового модуля SVP                |
| `sbg-release`    | Подготовка существующего release PR       |
| `sbg-announce`   | Текст анонса изменений с указанной версии |

В Codex вызывай скилл через `$sbg-…`, в Claude Code — `/sbg-…`.
Если скилл ещё не появился в текущей сессии, прочитай его `SKILL.md` по пути выше.
Подробности и примеры: [docs/agent/README.md](docs/agent/README.md).
